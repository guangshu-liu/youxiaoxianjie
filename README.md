# 识字闯关

给一个 6 岁、处于幼小衔接阶段的孩子做的识字游戏。一局 10 个字，答对转一次
转盘，转盘给积分（或动画片时间，或者什么也没有）。

**只有识字一科。** 这里原本是语文 / 数学 / 英语三科混排，英语还挂着一整套
OPW2 自然拼读课程表、词族解锁、最小对立对干扰项生成。全部退役了：孩子的
优先级是认字，一局里混三种东西只会让注意力散掉。

设计上的三个硬约束，所有代码都围绕它们：

1. **能离线玩。** 在线版有 Service Worker 全量预缓存，第二次打开起不依赖网络。
2. **零构建依赖。** 只用 Python 3 和 Node 标准库，没有 webpack/vite/npm 包。
   半年后回来还能构建成功。
3. **内容完全可控。** 题库是生成出来的 JSON，出题范围由一张字表白名单卡死。

---

## ⚠️ 先读这条：微信打不开 html 文件

**微信内置浏览器禁用了 `file://` 协议，并且不把 `.html` 当可预览文件。**
发过去的 html 附件，点开只会得到「无法预览」/「暂不支持打开此类文件」/白屏 ——
iOS 上常常连提示都没有。收发双方都一样，没有开关可调。

一句话：**微信只认 http/https URL，不认文件路径。**

所以分发给孩子只有一条路：**部署成 HTTPS 链接，发链接**。这正是本项目要
做在线版的原因，也是为什么要 PWA —— 详见下面「分发」一节。

单文件版仍然有用（电脑上双击即玩、飞行模式、归档备份），但它**不是**微信分发路径。

## 快速开始

```bash
npm run ziku       # 重新生成题库和字表（改了 tools/gen_ziku.py 之后跑）
npm run verify     # 生成器一致性 + 校验 + 测试 + 构建 + 产物测试，一条命令
npm run serve      # 本地预览 http://localhost:8080
npm run deploy     # 发布到 GitHub Pages，拿到可以发微信的链接
```

改完东西推手机之前，先跑 `npm run verify`。它做五件事：

| 命令 | 作用 |
|---|---|
| `npm run ziku:check` | 产物题库 / 字表是否与生成器一致（手改过 JSON 会在这里被挡住） |
| `npm run validate` | 题库结构 + 出题范围校验（构建前必跑） |
| `npm test` | 无头冒烟测试，从 `src/` 加载，95 项断言，0.3 秒 |
| `npm run build` | 产出两种产物 |
| `npm run test:build` | 同样的断言，但**从构建产物里抽内联代码跑** |

最后一条不是多余的。拼接 12 个 JS 文件有真实风险：某个文件少个结尾分号、
下一个文件以 `(` 开头，就会变成一个调用表达式 —— 这类 bug 只在运行时炸，
build 日志完全正常。`test:build` 验的就是「实际发出去的字节」。

## 题库

**题库不是手写的，是 `tools/gen_ziku.py` 生成的**，产出两个文件：

- `src/data/chinese.json` —— 296 道题，全部是 `choice`
- `src/data/zi_grade12.json` —— 166 个字（一年级 136 · 二年级 30），带拼音、
  笔画、部首、年级、组词

### 为什么用生成器

需求是「题库 ≤ 300 道，字限制在小学一、二年级」。手写 280 道题的选项，
必然出现这三类错，而且靠眼睛查不出来：

1. `answer` 指向一个不存在的选项
2. 两个选项都说得通（「（　）鸟」配上 马 / 牛 / 羊 —— 小马、小牛、小羊都是词）
3. 选项里混进了三年级的字

生成器把「字的范围」变成一条**机器可校验的约束**：字表里没有的字，根本
进不了选项。`selfcheck()` 还会逐题验证唯一正确答案，`--check` 保证产物可复现
（用了自写的 `dhash()` 而不是 Python 内置 `hash()`，后者每个进程换种子）。

### 八种题型

| 题型 | 题量 | 例子 |
|---|---|---|
| 看拼音选字 | 96 | 「yī」是哪个字？ |
| 看字选拼音 | 62 | 「花」读什么？ |
| 归类 | 40 | 下面哪个字说的是动物？ |
| 形近字辨析 | 31 | 日（　）出来了 —— 出 / 目 / 自 / 白 |
| 笔画 | 22 | 「天」一共有几笔？ |
| 部首 | 18 | 「花」的部首是什么？ |
| 反义词 | 17 | 「大」的反义词是哪个字？ |
| 偏旁 | 10 | 下面哪个字是「女」字旁？ |

两类题不能自动生成，是手工核对的：

- **形近字辨析**（31 条 `CURATED_SIMILAR`）—— 干扰项*也*可能填进去，必须逐条看
- **部首 / 偏旁** 的干扰项从一张 40 个儿童可辨认部首的表里取，不能用全集
  （全集里会出现 冖 / 忄 这种孩子没学过的）

### 改题库

改 `tools/gen_ziku.py` 里的 `CHARS` / `CURATED_SIMILAR` / `CATEGORY` 等常量，
然后：

```bash
npm run ziku        # 重新生成两个 JSON
npm run verify      # 生成器自检 + 构建校验 + 测试
```

`gen_ziku.py` 的 `LIMIT = 300` 和 `build.py` 的 `QUESTION_LIMIT = 300` 是同一个
上限的两道闸：前者在出题时挡住，后者在构建时独立复核一遍。

### 抽题不是均匀随机的

`30-bank.js` 按错题本加权：答错的题权重高（`1 + 1.5 × 错误次数`），连对两次
的题降到 `0.4`。均匀随机会让孩子已经滚瓜烂熟的字反复出现，而总写错的字
永远轮不到。

`40-runner.js` 再做两件事：

1. **第 1 题和第 10 题留给最有把握的两道。** 6 岁孩子最后一题的成败，
   直接决定他明天还想不想玩。
2. **同一题型不挨着。**「看拼音选字」占了题库的三分之一，不做这一步，
   一局看起来就像只有两种题。

### 题目长什么样

```jsonc
{
  "id": "zi-0001",
  "subject": "chinese",
  "type": "choice",
  "difficulty": 1,
  "unit": null, "family": null,     // 英语时代留下的字段，恒为 null
  "tags": ["看拼音选字"],
  "stem": { "text": "「yī」是哪个字？", "layout": "grid" },
  "options": [
    { "id": "a", "text": "力" }, { "id": "b", "text": "一" },
    { "id": "c", "text": "你" }, { "id": "d", "text": "七" }
  ],
  "answer": "b",
  "explain": "「一」读 yī，可以组词「一个」。"
}
```

`layout` 是选项的排布（`grid` 两列 / `row` 一行），写生成器时定死。

## 转盘

六个奖项，概率和为 100：

| 奖项 | 权重 |
|---|---|
| 动画片 10 分钟 | 5 |
| 1 分 | 30 |
| 2 分 | 20 |
| 5 分 | 15 |
| 10 分 | 10 |
| **下次好运（空奖）** | 20 |

**空奖就是空奖。** 它曾经是「再来一次」：占 20%，可重转最多 3 次，次数用完
兜底送 1 分。去掉了，两个原因：

- 重转把一次抽奖拖成几轮，孩子盯着盘转的时间比答题还长
- 「兜底送分」让空奖实际上不存在 —— 那就不叫空奖

盘面上写「下次好运」（84px 的扇区贴不下更长），结算条上写全
（`G.NO_PRIZE_TEXT = '无奖励，下次好运'`）。空奖的结果条是灰蓝色的，不是红色：
不中奖不是做错事，不该看起来像惩罚。

## 家长模式

入口在开始页，需要回答 `7 × 8`。功能：

- **三方审计** —— `balance` / `lifetime` / `redemptions` 交叉对账，对不上就报警
- **今日数据** —— 转盘次数、动画片分钟数、兑换次数
- **待确认兑换** —— 孩子提交的兑换在这里批准
- **识字范围** —— 字表全貌，以及哪些字还在错题本里（只读，没有开关）
- **学习数据** —— 按题型正确率、待巩固的题、最近 10 局
- **备份导出/导入** —— 存档 + 全部录音打包

> 原本还有个「英语学到第几单元」的解锁选择，英语退役后没了 ——
> 出题范围固定在字表内，没有可调的东西。

### 为什么必须有备份

**WebKit 自 iOS 13.4 起，7 天未访问就清空所有脚本可写存储**（localStorage、
IndexedDB 一视同仁），**对没加到主屏幕的站点绝对生效**。

iOS 微信内置浏览器**没有「添加到主屏幕」功能**，所以微信里玩的进度随时可能归零。
家长面板顶部会显示「上次备份：N 天前」，超过 7 天变红。**这条提示本身就是防丢失的主要手段。**

## 音频

现在整个游戏只有两条音频：`ui.spin`（转盘转动）和 `ui.win`（答对 / 中奖）。
识字题的题干和选项全是文字，没有听音题。

`tools/tts_gen.py` + `tools/audio_manifest.json` 这套 TTS 管线**保留着但闲置**。
留它的理由：这个游戏下一步最可能加的内容就是**每个字的读音**（166 个字，
看拼音选字题只显示拼音，孩子听一遍真人读音会更直接）。那时只需要在题库里
给题干加 `stem.audio`，跑 `npm run setup && npm run tts`，渲染器里的
喇叭按钮分支（`41-render-choice.js`）已经写好了。

加新音频的姿势没变：

```bash
npm run setup     # 扫描题库，把新引用的音频自动加进清单
npm run tts       # 只生成新增/变更的，已有的不动
```

清单里每条记 `text_sha1`，改了文本才会重新生成；也记 `sha1`，检测文件被外部改动。

### 命名规范（硬规则）

```
audio/ui/spin.mp3       →  id = "ui.spin"
audio/char/一.mp3        ←  不行：非 ASCII 文件名
audio/char/yi1.mp3      →  id = "char.yi1"
```

**全 ASCII 小写、无空格无中文。** 对象存储的 object key 对非 ASCII 的 URL
编码处理是坑，文件名污染是后期最难修的技术债。`id` 就是路径把 `/` 换成 `.`、
去掉扩展名 —— 代码引用音频不需要第二张映射表。

## 分发

### 主路径：GitHub Pages 链接（微信里打开）

```bash
npm run deploy       # 校验 → 测试 → 构建 → 同步 docs/ → 提交 → 推送
npm run deploy:dry   # 只构建并同步到 docs/，不碰 git
```

首次只有一步，装 gh 并登录：

```bash
brew install gh
gh auth login        # GitHub.com → HTTPS → Login with a web browser
```

然后 `npm run deploy`。登录之后脚本会**自动**建仓库、从 GitHub 账号推断 git 身份
（用 `<id>+<login>@users.noreply.github.com` 当提交邮箱，不暴露真实邮箱）、
开启 Pages，最后打印可以发微信的链接。以后更新内容只需 `npm run deploy`。

> 不想装 gh 也行，脚本会在每一步告诉你缺什么：手配 `git config --global user.name/user.email`、
> 在 <https://github.com/new> 建一个 Public 仓库（**不要勾任何初始化选项**）、
> 手工开 Settings → Pages → Deploy from a branch → `main` / `/docs`。
> 用 SSH key 或 Personal Access Token 认证也可以。gh 只是把这些合成一条命令。

**为什么 GitHub Pages**：免费、自动 HTTPS、**不需要 ICP 备案**，当天就能用。
腾讯云 COS 在国内更快更稳，但大陆地域绑自定义域名必须完成 ICP 网站备案
（首次 1–3 周），且 2024-01-01 后创建的存储桶用默认域名不支持静态网站。
如果你已有备案域名，把 `docs/` 里的内容传上去即可，构建产物完全一样。

### 让孩子真正离线玩：添加到主屏幕

在 Safari 里打开链接 → 分享 → **添加到主屏幕**。这样做有两个好处：

1. **离线可玩。** Service Worker 已经预缓存了全部 11 个资源
   （含两条音频，约 288 KB），之后飞行模式也能玩。
2. **存档不会被清掉。** iOS 对 Safari 里的站点有「7 天未访问即清空存储」的规则，
   但**主屏幕 Web App 有独立的持久化存储，不受这条规则限制**。
   这比反复提醒家长备份有效得多。

> 微信内置浏览器**没有**「添加到主屏幕」，所以这一步必须在 Safari 里做。
> 微信里也能正常玩，只是受 7 天规则约束 —— 家长面板里的备份提示仍然重要。

### 备用：单文件版

```bash
npm run build:single    # → output/幼小衔接-v1.0.html（约 284 KB）
```

全内联，含 base64 音频，零外部依赖。**在电脑上双击即玩**，适合家长自己检查、
归档备份。不要在微信里发给别人 —— 见本文开头。

## 真机验收清单

无头测试能覆盖逻辑，**覆盖不了音频、微信和离线**。以下必须在真机上过一遍
（iPhone + iPad 各一次）：

- [ ] Safari 里打开 Pages 链接，答对一题后转盘能转、有声音
- [ ] **微信内置浏览器**里打开同一链接，声音能播（最不确定的一条）
- [ ] 微信里关掉重开，进度还在
- [ ] Safari 里「添加到主屏幕」，从主屏幕图标启动能玩
- [ ] 主屏幕启动后开飞行模式，完整玩一局（音频 + 存档都要正常）
- [ ] 转盘转到「下次好运」时，孩子看得懂那是没中奖（而不是以为卡住了）
- [ ] 家长面板导出备份 → 清空存储 → 导入，数据完整
- [ ] 故意把手机时间回拨，确认兑换被冻结且家长面板报警

自检页：在链接后面加 `#selftest`，会逐项检测环境、音频、存储、配额，
并生成一份可复制的报告。

## 明确不做的事

这些都被考虑过并否决了，写在这里是为了防止将来重新想起来又做一遍：

- ❌ **服务端积分签名** —— 为保护 1 元兑换而后端化，而兑现者就是家长本人。
  且直接违背"单文件离线可玩"的核心需求。
- ❌ **存档 XOR 混淆** —— 对 6 岁孩子和加密一样无用（两个他都不会），
  只会让将来调试存档变难。
- ❌ **Canvas 反调试 / 代码混淆** —— 收益为零。
- ❌ **`<audio>` 元素做音频** —— iOS 上每个元素都要单独在 gesture 里解锁。
  Web Audio 一次 `ctx.resume()` 解决。
- ❌ **ES Module** —— `<script type="module">` 在 `file://` 下被 CORS 拦截，
  而单文件版正是要在 `file://` 下打开。
- ❌ **空奖兜底送分 / 重转** —— 见「转盘」一节。
