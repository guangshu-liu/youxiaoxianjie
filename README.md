# 幼小衔接闯关

给一个 6 岁、处于幼小衔接阶段的孩子做的闯关游戏。一局 10 题
（**语文 3 · 数学 3 · 英语 4**），答对转一次转盘，转盘给积分
（或动画片时间，或者什么也没有）。题库 600 道。

三科各管一件事：

| 科目 | 范围 |
|---|---|
| 语文 | 一年级认字 + 拼音。字形题绕开读音；拼音只出现在「看拼音选字 / 声母韵母」两类题里 |
| 数学 | 分两档：基础档 20 以内不进位加减（课标范围），进阶档 100 以内进位 / 退位 + 数学思维（拆数凑十、比大小、找规律、应用题、分类）。正确率达标才解锁进阶档 |
| 英语 | OPW1 字母复习 60 道 + OPW2 短元音 140 道（25 个词族 / 108 个 CVC 词）：听音选词、辨短元音、押韵、拼合、跨词族归类、找真词，基础档 U1–U4（a/e/i），进阶档 U5–U8 + 混合。听音题带语音 |

设计上的三个硬约束，所有代码都围绕它们：

1. **能离线玩。** 在线版有 Service Worker 全量预缓存，第二次打开起不依赖网络。
2. **零构建依赖。** 只用 Python 3 和 Node 标准库，没有 webpack/vite/npm 包，
   也不需要 `pip install`。半年后回来还能构建成功。
3. **内容完全可控。** 题库是生成出来的 JSON，出题范围由字表白名单和词表卡死。

## ⚠️ 先读这条：微信打不开 html 文件

**微信内置浏览器禁用了 `file://` 协议，并且不把 `.html` 当可预览文件。**
发过去的 html 附件，点开只会得到「无法预览」/「暂不支持打开此类文件」/白屏 ——
iOS 上常常连提示都没有。收发双方都一样，没有开关可调。

一句话：**微信只认 http/https URL，不认文件路径。**

所以分发给孩子只有一条路：**部署成 HTTPS 链接，发链接**。这正是本项目要
做在线版的原因，也是为什么要 PWA —— 详见下面「分发」一节。

单文件版仍然有用（电脑上双击即玩、飞行模式、归档备份），但它**不是**微信分发路径。

## 快速开始

```bash
npm run qbank      # 重新生成三科题库（改了 tools/gen_*.py 之后跑）
npm run audio      # 生成缺失/变更的语音（英语单词）
npm run audio:health # 语音完整体检：清单 / 文件 / 解码音量 / 三处副本 / 两端映射
npm run verify     # 生成器一致性 + 语音 + 校验 + 测试 + 构建 + 网页版同步 + 小程序 + 语音体检
npm run serve      # 本地预览 http://localhost:8080
npm run deploy     # 发布到 GitHub Pages，拿到可以发微信的链接
npm run mp:build   # 生成微信小程序的题库/逻辑/音频（见 miniprogram/README.md）
```

改完东西推手机之前，先跑 `npm run verify`。它做六件事：

| 命令 | 作用 |
|---|---|
| `npm run qbank:check` | 三科题库是否与生成器一致（手改过 JSON 会在这里被挡住） |
| `npm run audio:check` | 每条被引用的语音是否都已生成、且与文本一致 |
| `npm run validate` | 题库结构 + 配比 + 出题范围校验（构建前必跑） |
| `npm test` | 无头冒烟测试，从 `src/` 加载，125 项断言，0.5 秒 |
| `npm run build` | 产出两种产物 |
| `npm run test:build` | 同样的断言，但**从构建产物里抽内联代码跑**，126 项 |
| `npm run mp:build` + `mp:test` | 生成小程序产物并跑 79 项断言（见 `miniprogram/README.md`） |

最后一条不是多余的。拼接 13 个 JS 文件有真实风险：某个文件少个结尾分号、
下一个文件以 `(` 开头，就会变成一个调用表达式 —— 这类 bug 只在运行时炸，
build 日志完全正常。`test:build` 验的就是「实际发出去的字节」。

冒烟测试跑在 Node 的 `vm` 沙箱里，DOM 是最小桩。**桩上的
`className`/`classList` 和事件监听必须做真** —— 早先 `classList` 自己抱一个
`Set`，而 `G.el` 是用 `className` 赋值的，两边不通，于是渲染器里
`classList.contains('stem-text')` 永远返回 `false`。断言照样「通过」，
但什么都没验证。现在两者接在同一份数据上，第 8 节因此能真的抓住
「题干没画出来」这类 bug（见下面的音频一节）。

## 题库

**题库不是手写的，是三个生成器算出来的**，产出五个文件：

| 文件 | 由谁生成 | 内容 |
|---|---|---|
| `src/data/chinese.json` | `gen_ziku.py` | 200 道，全部 `choice` |
| `src/data/math.json` | `gen_shuxue.py` | 200 道 |
| `src/data/english.json` | `gen_yingyu.py` | 200 道 |
| `src/data/zi_grade1.json` | `gen_ziku.py` | 136 个一年级字，带拼音、笔画、部首、年级、组词 |
| `src/data/english_audio.json` | `gen_yingyu.py` | 英语要哪些语音、读什么 |

三个生成器共用 `tools/qbank.py` —— 确定性 RNG、拼题、通用校验都只写一遍。
三家的字段必须完全一致，运行时的渲染器只认一套 schema，任何一家走样都会
在真机上白屏。

### 为什么用生成器

需求是「三科各 200 道，语文只用一年级字并包含拼音，数学计算与思维各半、
难度 1 / 2 各 100 道，英语 OPW1 复习 60 + OPW2 短元音 140、同样两档各 100」。
手写三百道题的选项，必然出现这四类错，而且靠眼睛
查不出来：

1. `answer` 指向一个不存在的选项
2. 两个选项都说得通（「（　）鸟」配上 马 / 牛 / 羊 —— 小马、小牛、小羊都是词；
   「日」加一笔既可以是「目」也可以是「白」）
3. 选项里混进了超纲的字、超纲的数、超纲的词
4. 字形/字义题里混进了拼音（拼音只允许出现在两类拼音题里）

生成器把这几条范围变成**机器可校验的约束**。每个生成器的 `selfcheck()` 里
都有一组针对本科目的断言，例如：

- 语文：「日」加一笔的选项里，`PLUS_ONE` 表上的合法答案**只能有一个**
- 数学：按题型用正则解析题干，**独立重算一遍答案**，再断言四个选项里
  恰好一个等于它；另外按 `difficulty` 卡死两档边界 —— 基础档不许出现
  进位 / 退位或超过 20 的数，进阶档不许退化成数数就能做的题
- 英语：OPW1 听音选字母的四个选项**两两不同音**（`c` / `k` / `q` 同时出现
  就是两个正确答案 —— `q` 读 /kw/，但孩子拿 K 答「queen」完全说得通）；
  大小写配对题**只能是同一种大小写**；字母顺序题按字母表**独立重算**；
  OPW2 听音选词的四个选项**必须同词族**（不然看首字母就能选，不用听）；
  辨短元音题的答案**独立重算**音频词中间的元音；押韵题选项里**只有一个**
  和题干同韵尾；拼合题同族四个词首字母两两不同；跨词族归类严格是
  「三个同韵尾 + 一个异类」；找真词的三个假词**都不在真词词典表里**。
  另外还卡死基础档只碰 U1–U4 的词、进阶档至少 60 道涉及 U5–U8 的词，
  以及全库不许有句子填空

`--check` 保证产物可复现（用了自写的 `dhash()` 而不是 Python 内置 `hash()`，
后者每个进程换种子），所以「生成器改了但产物没重跑」会在 `npm run verify`
第一步就被挡住。

### 三科的题型

**语文 200 道**（一年级认字 + 拼音）

| 题型 | 题量 | 例子 |
|---|---|---|
| 看拼音选字 | 47 | 「gǒu」是哪个字？ |
| 声母 / 韵母 | 30 | 下面哪个是声母？ |
| 归类 | 30 | 下面哪个字说的是动物？ |
| 加一笔 / 减一笔 | 23 | 「日」加一笔可以变成哪个字？ |
| 笔画 | 22 | 「天」一共有几笔？ |
| 反义词 | 20 | 「大」的反义词是哪个字？ |
| 部首 | 20 | 「花」的部首是什么？ |
| 偏旁 | 8 | 下面哪个字是「女」字旁？ |

**数学 200 道**（计算与思维各半，难度 1 / 2 各 100 道）

| 题型 | 题量 | 难度 | 例子 |
|---|---|---|---|
| 基础计算 | 68 | 1 | 2 + 3 = ?　／　14 + 5 = ?（20 以内，不进位 / 不退位） |
| 比大小 | 18 | 1 | 哪个最大？／ A 和 B 哪个大？ |
| 分类 | 14 | 1 | 下面哪个数和其他三个不一样？ |
| 直接计算 | 32 | 2 | 66 + 4 = ?（进位加 / 退位减） |
| 拆数凑十 | 28 | 2 | 25 = 20 + ?　／　7 + 8 = 7 + 3 + ? |
| 应用题 | 20 | 2 | 一题一个模板，加 7 减 7 |
| 找规律 | 20 | 2 | 公差 2–5 / 10 / 12–20 的等差数列 |

基础档的干扰项也卡在本档范围内（10 以内题只给 10 以内的错数），
不然「2 + 3」旁边摆个 15，孩子一眼就排除，那道题等于白出。

**英语 200 道**：OPW1 复习 60 + OPW2 短元音 140，难度 1 / 2 各 100 道。

孩子已经学完 OPW1（字母本）、正在读 OPW2（Short Vowels），所以字母题只留
60 道保温，主要时间给 CVC 词。词源是两张表：`LETTER_WORDS`（26 字母 × 3 词）
和 `FAMILIES`（25 个词族、108 个 CVC 词，U1–U8 单元顺序原样保留）。

| 档 | 题型 | 题量 | 例子 |
|---|---|---|---|
| 1 | 听音选字母 / 大小写配对 / 字母顺序 / 元音字母 | 26 / 26 / 4 / 4 | OPW1 复习：听 `ant` 选 A |
| 1 | 听音选词 | 16 | 听 `yam`，从 `jam / dam / ham / yam` 里选（同词族，带语音） |
| 1 | 辨短元音 | 8 | 听 `bad`，中间是哪一个元音？→ `a`（带语音） |
| 1 | 押韵配对 | 8 | 哪个词和 `ram` 的结尾音一样？→ `jam` |
| 1 | 拼合 CVC | 8 | `d + am` 拼起来是哪个词？→ `dam` |
| 2 | 听音选词 | 28 | U5–U8 的 i(2) / o / u 词族，同族四选一（带语音） |
| 2 | 辨短元音 | 16 | 五个短元音混合听辨（带语音） |
| 2 | 跨词族归类 | 40 | 三个 `-am` 词里混一个 `-id`，挑出异类 |
| 2 | 找真词 | 16 | `vin / jin / zin / tin` 里只有 `tin` 是真词 |

合计 200 道：OPW1 复习 60、OPW2 新题 140（基础 40 / 进阶 100），进阶档主力
是跨词族归类，找真词只占 16 道。**没有句子填空**：历史 OPW2 版本的 27 道
句子题，要么音频念出答案，要么要求 6 岁孩子自己读整句，两条路都不成立。

`x` 例外 —— 英语里几乎没有以 x 开头的日常词，OPW1 教的是词尾的 x
（`box` / `fox` / `six`），所以 x 不参与听音选字母。语音清单 88 条由题库
**反推**生成（66 个 OPW2 短元音词 + 22 个 OPW1 复习词），94 道题带喇叭。

### 难度分档与解锁

题库里每道题带 `difficulty`（1 基础 / 2 进阶），但**光分档没用，得让抽题真的看它**。
`src/js/30-bank.js` 的 `Bank.levelOf(save, subject)` 取最近 20 次**本科目**作答：

| 情况 | 出的档 |
|---|---|
| 记录不足 6 次（新用户 / 清了存档 / 题库换过 id） | 只出 1 |
| 正确率 ≥ 80% | 1 和 2 都出 |
| 正确率 < 80% | 退回只出 1 |

分科判断：数学全对不会让英语一起升档。`drawOne` 先按档过滤、再按错题本加权；
本档的题被一局抽光时允许本档重题，**不会借这个机会把超纲题放进来**。

用 20 次窗口是为了别因为一局失手就立刻把孩子打回原地；阈值和窗口长度都
写在 `levelOf()` 里，改一处即可，改完跑 `npm run verify`。

数学的两档差距最大：难度 1 是 20 以内不进位加减（课标 5-6 岁要求 10 以内，
一年级上到 20 以内），难度 2 的 100 以内进位 / 退位是**人教版二年级上**。
零基础的孩子以前分科一局 10 道数学能撞上 8 道进位加，现在先练基础档。
语文两档差距小；英语两档现在是**内容分层**：基础档是 OPW1 字母复习 +
U1–U4 的 a / e / i，进阶档是 U5–U8 的 o / u 与跨词族混合题 —— 孩子正在
学的 OPW2 后期内容全在进阶档，不会因为「字母题做熟了」就一直停留在字母上。

### 配比是硬约束

`tools/build.py` 的 `SUBJECT_MIX = {chinese: 3, math: 3, english: 4}` 是**一局构成**
的唯一真相源；`BANK_RATIO = 1:1:1` 是**题库题量**的配比（三科各 200）。
这两个数现在是分开的：题库等量，一局仍然是 3:3:4 的混合局（小程序则改成
「选一科、10 题」，见 `miniprogram/README.md`）。

1. 每个生成器的 `LIMIT`（三科各 200，合计 600）
2. `build.py` 构建时校验每科题量对不对
3. 产物里的 `G.DATA.mix`，运行时的一局构成直接读它

一局 10 道就是 3 语文 + 3 数学 + 4 英语。**按科目配额抽满，不是一起抽再按
比例挑** —— 一起抽的话科目分布是概率结果不是配额，再叠上错题加权，一局
很可能抽出 8 道英语、1 道语文。

### 抽题不是均匀随机的

`30-bank.js` 按错题本加权：答错的题权重高（`1 + 1.5 × 错误次数`），连对两次
的题降到 `0.4`。均匀随机会让孩子已经滚瓜烂熟的字反复出现，而总写错的字
永远轮不到。

`40-runner.js` 再做两件事：

1. **第 1 题和第 10 题留给最有把握的两道。** 6 岁孩子最后一题的成败，
   直接决定他明天还想不想玩。
2. **相邻两题尽量不同科、同科内尽量不同题型。** 纯随机打散的话，一局里
   出现「连着 4 道英语」的概率相当高。实测同一科目相邻的比例是 2.2%，
   纯随机约 32%。

## 转盘

六个奖项，概率和为 100：

| 奖项 | 权重 |
|---|---|
| 动画片 10 分钟 | 5 |
| 1 分 | 30 |
| 2 分 | 20 |
| 5 分 | 15 |
| 10 分 | 10 |
| **下次好运（空奖）** | 20 |

**空奖就是空奖。** 它曾经是「再来一次」：占 20%，可重转最多 3 次，次数用完
兜底送 1 分。去掉了，两个原因：

- 重转把一次抽奖拖成几轮，孩子盯着盘转的时间比答题还长
- 「兜底送分」让空奖实际上不存在 —— 那就不叫空奖

### 盘面上要看得到奖项

每个奖项有两个名字，写在 `G.PRIZES` 里：

| 字段 | 用在哪 | 例子 |
|---|---|---|
| `face` | 盘面上，贴在扇区里 | `📺 10分钟`、`1分`、`下次好运` |
| `label` | 结算条、家长面板 | `动画片 10 分钟`、`1 分`、`下次好运` |

分开是因为盘面位置太小：六个扇区里最窄的 `tv10` 只有 18°，在能放下的半径
区间里，标签最多占 72px 宽、两三个字。结算条有整行宽度，那里可以说全。

**盘面上的文字要沿半径方向排**，不能像普通文字那样横着写 —— 横着写的
72px 标签，在半径 76px 处横跨 `2·asin(36/76) ≈ 56°` 的弧，而最窄的扇区只有
18°，一定压到隔壁。做法是用扇区中心角 `s.center` 把标签转到位，再沿半径推出去：

```js
label.style.transform =
  'translate(-50%, -50%) rotate(' + s.center + 'deg)' +
  ' translateY(-76px) rotate(' + text + 'deg)';   // text = 下半区翻 180°
```

`translate(-50%, -50%)` 把标签的原点挪到自己的中心，然后绕**扇区中心**旋转
再沿半径外推 76px。最后那个 `rotate(±90deg)` 是为了让下半区的字不倒过来 ——
`s.center > 180` 的扇区转 `-90°`，否则 `+90°`。

这个几何是可以算出来的，不用肉眼试：标签未旋转时的中心在
`(cx + LW/2, cy + LH/2)`（`LW/LH` 是标签自己的宽高），变换后它的四个角
必须同时落在 ① 盘面内 ② 自己的扇区角度内 ③ 不压住中间的轴心。六个扇区
改过三版才全过 —— 第一版用 `translateY(-38%)`，38% 是按标签自己 14px 的
高度算的，实际只推出去了 5px，六个标签全叠在轴心底下；第二版半径对了但
`line-height: 1.1` 让标签高了 0.5°，`tv10` 那 18° 的扇区就溢出去了；
第三版 `line-height: 1` 才过。

空奖的结果条是灰蓝色的，不是红色：不中奖不是做错事，不该看起来像惩罚。

## 家长模式

入口在开始页，需要回答 `7 × 8`。功能：

- **三方审计** —— `balance` / `lifetime` / `redemptions` 交叉对账，对不上就报警
- **今日数据** —— 转盘次数、动画片分钟数、兑换次数
- **待确认兑换** —— 孩子提交的兑换在这里批准
- **语文认字范围** —— 一年级字表全貌，以及哪些字还在错题本里（只读，没有开关）
- **学习数据** —— 三科分开统计，各自按题型出正确率、待巩固的题、最近 10 局
- **备份导出/导入** —— 存档 + 全部录音打包

> 原本还有个「英语学到第几单元」的解锁选择，改成两档难度门控后没了 ——
> 出题范围由生成器锁死，家长这边没有可调的旋钮。

### 为什么必须有备份

**WebKit 自 iOS 13.4 起，7 天未访问就清空所有脚本可写存储**（localStorage、
IndexedDB 一视同仁），**对没加到主屏幕的站点绝对生效**。

iOS 微信内置浏览器**没有「添加到主屏幕」功能**，所以微信里玩的进度随时可能归零。
家长面板顶部会显示「上次备份：N 天前」，超过 7 天变红。**这条提示本身就是防丢失的主要手段。**

## 音频

音频分两层，**是两条完全不同的路径**：

| | 来源 | 文件 | 谁用 |
|---|---|---|---|
| **音效** | 代码合成的振荡器 | **零个文件** | 点按钮、答对、答错、转盘、中奖 |
| **语音** | `tools/gen_audio.py` 生成 | 88 个 `.m4a`，约 597 KB | 英语 94 道听音题（听音选字母 / 听音选词 / 辨短元音） |

### 音效：为什么一个文件都不放

`audio/ui/` 原本放着两个 12 KB 的占位音（`spin.wav` / `win.wav`），已经删掉。
现在所有音效由 `src/js/21-sfx.js` 现场合成 —— `createOscillator` 加指数包络，
`ui.correct` 是三连上行音（C5-E5-G5），`ui.wrong` 是一声轻的下行音，
`ui.spin` 是 26 声间隔从 45ms 递增到 260ms 的噪声「咔哒」。

换成合成有三个理由：

1. **不会解码失败。** 音频文件播不出来的原因有一打（格式、CORS、`file://`
   下的相对路径、微信的自动播放策略），任何一个都能让按钮变哑。振荡器没有
   解码这一步。
2. **不占体积。** 单文件版要把音频 base64 内联，内联进去的每个字节都乘 1.33。
3. **可以改。** 觉得答对的声音太尖，改一个频率数字就行，不用重新生成文件。

包络用 `exponentialRampToValueAtTime` 从 `0.0001` 起降到 `0.0001` 收
（不能直接用 0，指数曲线不接受）。**波形硬起硬停会「啪」一声** —— 那是
50Hz 上下的方波边沿，比音效本身还响。

### 点哪儿都有声音：用捕获阶段的事件委托

「点按钮没声音」这个 bug 的根因是**没有任何一处代码播过点击音**。修法不是
在每个按钮上加一行 —— 那要求以后每个新按钮都记得写。改成在 `document` 上
挂一个**捕获阶段**的 click：

```js
document.addEventListener('click', function (e) {
  var btn = e.target.closest && e.target.closest('button, .tap');
  if (!btn || btn.disabled || btn.classList.contains('locked')) return;
  if (btn.hasAttribute('data-sfx-off')) return;   // 选项按钮自己播对错音
  play('ui.tap');
}, true);   // ← 捕获，不是冒泡
```

捕获阶段先于任何业务逻辑执行，所以就算按钮的 handler 里 `preventDefault`
或者立刻把按钮 `disabled` 掉，声音也已经发出去了。

答对答错的音不在这里播：`05-ui.js` 的 `feedback()` 里有一句
`G.Audio.play(correct ? 'ui.correct' : 'ui.wrong')`。**这行以前只写在注释里，
从来没实现过** —— 这是「答对了没声音」的直接原因。

### 一个页面只能有一个 AudioContext

`21-sfx.js` 不自己 new `AudioContext`，它调 `G.Audio._ensureCtx()` 复用
`20-audio.js` 那一个。两个 context 是 iOS 上最常见的「明明解锁了还是没声音」：
手势解锁只会 resume 当前那个，另一个一直是 `suspended`。

**`ctx.resume()` 必须在真实手势的调用栈里同步触发。** 桌面 Chrome 的
「粘性激活」会掩盖这个问题 —— 在电脑上点一次之后，之后所有页面加载都不需要
再解锁，所以这个 bug 只在 iOS Safari / 微信里显形。`unlock()` 同时挂了
`pointerdown` 和 `touchend` / `click`，因为老版本 WebKit 上 `pointerdown`
不一定被当成用户手势。

### 语音：macOS 自带 TTS，零安装

`tools/gen_audio.py` 用 `say` 出声、`afconvert` 转 AAC，**不需要 pip install
任何东西**。这一条是硬要求 —— 被删掉的 `tools/tts_gen.py` 依赖 `edge-tts`，
而这个包从来没装上过，这就是整套语音管线一直没产出、题库里 0 条音频引用的原因。

```bash
npm run audio          # 生成新增/变更的，已有的不动
npm run audio:check    # 只检查清单齐不齐，不写文件（CI / verify 用）
npm run audio:health   # 完整体检：解码 88 条听音量、比对三处副本和两端映射
```

`audio:check` 只回答「文件在不在」，回答不了「文件能不能响」。历史上出过
「文件齐了但是占位蜂鸣」和「网页版副本没同步」两件事，所以 `check_audio.py`
分五层查：引用双向一致 → m4a 头与时长 → 实际解成 PCM 看峰值 / RMS / 有声
占比 → `audio/` · `docs/audio/` · `miniprogram/generated/audio/` 逐字节一致
→ `data.js` 和 `audio.js` 的映射都指向存在的文件。任何一层挂了都非 0 退出，
`npm run verify` 最后一步会跑它。

AAC 32 kbps 大约 7 KB 一个词，换 WAV 是 60 KB。88 个文件合计约 597 KB，
单文件版内联后约 795 KB —— 这是单文件版 1.1 MB 的主要构成。

`collect()` 会**双向**核对题目和清单：

- 题目引用了清单里没有的 id → 报错（不是静默跳过）
- 清单里有、没有任何题目引用的 id → 也报错

只查一个方向的话，删了题之后残留在清单里的语音会一直被打包进产物，
没人发现。

清单里每条记 `text_sha1`（文本变了才重新合成）和 `sha1`（检测文件被外部
改动）。所以「改了单词却忘了重跑 `npm run audio`」会在 `npm run verify`
的第二步被挡住。

### 命名规范（硬规则）

```
en/ant.m4a            →  id = "en.ant"
audio/char/一.mp3      ←  不行：非 ASCII 文件名
```

**全 ASCII 小写、无空格无中文。** 对象存储的 object key 对非 ASCII 的 URL
编码处理是坑，文件名污染是后期最难修的技术债。`id` 就是路径把 `/` 换成 `.`、
去掉扩展名 —— 代码引用音频不需要第二张映射表。

### 听音题的音频就是题目本身

94 道听音题是**先听后答**：喇叭在答题前就自动播一遍（`stem.audio` 指向
`en.ant`，孩子听到 ant 选 A；指向 `en.yam`，就从 `jam / dam / ham / yam`
里挑出听到的那个）。所以喇叭必须在答题前就能点 —— 藏起来的话这道题就
没有任何信息了，`smoke_test.js` 有一条断言挡着。

反过来说，**只有听音题能带音频**：拼合 CVC、押韵配对、跨词族归类、找真词
都是看词做题，一念就等于把答案念出来了。`smoke_test.js` 也把这条写成了
断言。历史上 OPW2 版本有 27 道句子填空，音频念的是填好空的整句，于是得
用 `stem.audioReveals` 把喇叭藏到答完之后；这一版没有句子题，那套机制
一并删掉了 —— 留着一个没有任何题目使用的分支，对应的测试只会变成空断言。

`gen_yingyu.py` 的 `selfcheck()` 断言语音清单和题库双向对得上，
`qbank.py` 的 `selfcheck_common()` 断言有音频的题一定有文字题干。

### 题干文字和喇叭按钮都要画出来

渲染器里这里曾经是 `if (stem.audio) … else if (stem.text) …`，
**结果是英语题的文字题干全都不显示**，屏幕上只剩一个没有说明的喇叭。
现在两者都画，`qbank.py` 和 `smoke_test.js` 各有一条断言挡着不让它退回去。

## 分发

### 主路径：GitHub Pages 链接（微信里打开）

```bash
npm run deploy       # 校验 → 测试 → 构建 → 同步 docs/ → 提交 → 推送
npm run deploy:dry   # 只构建并同步到 docs/，不碰 git
```

首次只有一步，装 gh 并登录：

```bash
brew install gh
gh auth login        # GitHub.com → HTTPS → Login with a web browser
```

然后 `npm run deploy`。登录之后脚本会**自动**建仓库、从 GitHub 账号推断 git 身份
（用 `<id>+<login>@users.noreply.github.com` 当提交邮箱，不暴露真实邮箱）、
开启 Pages，最后打印可以发微信的链接。以后更新内容只需 `npm run deploy`。

> 不想装 gh 也行，脚本会在每一步告诉你缺什么：手配 `git config --global user.name/user.email`、
> 在 <https://github.com/new> 建一个 Public 仓库（**不要勾任何初始化选项**）、
> 手工开 Settings → Pages → Deploy from a branch → `main` / `/docs`。
> 用 SSH key 或 Personal Access Token 认证也可以。gh 只是把这些合成一条命令。

**为什么 GitHub Pages**：免费、自动 HTTPS、**不需要 ICP 备案**，当天就能用。
腾讯云 COS 在国内更快更稳，但大陆地域绑自定义域名必须完成 ICP 网站备案
（首次 1–3 周），且 2024-01-01 后创建的存储桶用默认域名不支持静态网站。
如果你已有备案域名，把 `docs/` 里的内容传上去即可，构建产物完全一样。

### 让孩子真正离线玩：添加到主屏幕

在 Safari 里打开链接 → 分享 → **添加到主屏幕**。这样做有两个好处：

1. **离线可玩。** Service Worker 已经预缓存了全部 97 个资源
   （含 88 条语音），之后飞行模式也能玩。
2. **存档不会被清掉。** iOS 对 Safari 里的站点有「7 天未访问即清空存储」的规则，
   但**主屏幕 Web App 有独立的持久化存储，不受这条规则限制**。
   这比反复提醒家长备份有效得多。

> 微信内置浏览器**没有**「添加到主屏幕」，所以这一步必须在 Safari 里做。
> 微信里也能正常玩，只是受 7 天规则约束 —— 家长面板里的备份提示仍然重要。

### 备用：单文件版

```bash
npm run build:single    # → output/幼小衔接-v1.0.html（约 1.1 MB）
```

全内联，含 base64 音频，零外部依赖。**在电脑上双击即玩**，适合家长自己检查、
归档备份。不要在微信里发给别人 —— 见本文开头。

1.1 MB 里约 795 KB 是 base64 之后的英语语音（597 KB × 1.33）。这是「英语要有
听力题」和「单文件要能双击打开」两条要求撞在一起的结果。在线版不受影响，
它的语音是分离的 88 个文件，首屏不加载。

## 待定参数

**`maxPointsPerDay: 60`** —— 积分只从转盘来，每局期望 2.45 分
（`0.30×1 + 0.20×2 + 0.15×5 + 0.10×10`），所以 60 分要约 **24 局**才触顶。
正常玩一天到不了，这条是防异常的天花板，不是配额。

500 分（1 元）按每天玩满上限算要约 9 天。改 `src/js/00-core.js` 的 `G.LIMITS`。

> 初版需求写的是「50 分兑换 1 元」，实现从第一天起就是 500 —— 见
> `prompts/1、游戏基本设定.md` 第六节的待确认项。

## 明确不做的事

这些都被考虑过并否决了，写在这里是为了防止将来重新想起来又做一遍：

- ❌ **服务端积分签名** —— 为保护 1 元兑换而后端化，而兑现者就是家长本人。
  且直接违背"单文件离线可玩"的核心需求。
- ❌ **存档 XOR 混淆** —— 对 6 岁孩子和加密一样无用（两个他都不会），
  只会让将来调试存档变难。
- ❌ **Canvas 反调试 / 代码混淆** —— 收益为零。
- ❌ **`<audio>` 元素做音频** —— iOS 上每个元素都要单独在 gesture 里解锁。
  Web Audio 一次 `ctx.resume()` 解决。
- ❌ **用音频文件做音效** —— 曾有过两个 12 KB 的占位 WAV，删了。点按钮的
  「嗒」声、对错音、转盘音全部用振荡器现场合成：不占体积、不会解码失败、
  能直接改参数（见「音频」一节）。只有**人声**（英语单词）才落成文件。
- ❌ **ES Module** —— `<script type="module">` 在 `file://` 下被 CORS 拦截，
  而单文件版正是要在 `file://` 下打开。
- ❌ **空奖兜底送分 / 重转** —— 见「转盘」一节。
