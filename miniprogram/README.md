# 微信小程序版

同一套题库、同一套组局逻辑，界面用 WXML 重写，奖励从「转盘抽奖 + 积分兑现金」
改成**确定性的星星与徽章**。

## 为什么改掉了转盘

微信《常见拒绝情形》3.2.8.9 把「有奖竞猜和抽奖」列为违规，积分兑换现金也属于
高危项。即使只做体验版不过审，这套机制也不值得留着 —— 而这个游戏真正的动力
本来就不是赌运气。

现在的规则：**选一科，一局 10 题**（三科各 200 道题）。答对 **9–10 题 3 星**、
**6–8 题 2 星**、**0–5 题 1 星**。阈值按科目分开配置，以后要单独调数学不用改逻辑。
星星累计到 **10 / 30 / 50 / 100** 各解锁一个徽章（🍟 薯条 / 🤖 布鲁克 / 📺 动画片 / 🛒 超市）。

## 前置

### 1. 安装开发者工具

[下载地址](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
Mac 上也可以 `brew install --cask wechatwebdevtools`。

### 2. 注册小程序，拿 AppID

只有注册后才能**真机预览**和**上传体验版**；游客模式只能在电脑模拟器里跑。
注册免费，个人主体即可，需要身份证 + 银行卡实名。

1. 打开 <https://mp.weixin.qq.com/> → **立即注册** → 选 **小程序**（不要选订阅号/服务号）。
2. 用一个**没在微信公众平台注册过**的邮箱，填密码，去邮箱点激活链接。
3. 主体类型选 **个人**，填身份证姓名/号码、管理员手机号，短信验证。
4. 登录后台 → **开发管理 → 开发设置**，复制 **AppID**（`wx` 开头 16 位）。

> 体验版**不需要**：微信认证（约 30 元）、ICP 备案、类目审核、代码审核。
> 这些都只卡「正式发布」。但备案周期 1–4 周且不支持加急，只要打算上线，
> 就在做体验版的同时把备案提了 —— 见「正式上线：备案 → 提交审核 → 发布」。

### 3. 把 AppID 写进项目

```bash
npm run mp:appid -- wx1234567890abcdef   # 会先校验格式再写盘
npm run mp:appid -- --check              # 随时复核当前用的是不是正式号
```

> **只需要 AppID，不需要 AppSecret。** 密钥是服务端凭据，只在调用
> `code2Session` / 获取 access_token 这类接口时用；本项目没有服务端，
> 上传代码靠的是开发者工具里登录的微信账号。
> **绝对不要把 AppSecret 写进仓库或前端代码** —— 拿到它就能以你的
> 小程序身份调用服务端接口。

### 4. 题干朗读：不需要任何后台配置

孩子认字少，题目靠读出来。最初试过微信官方的**同声传译**插件
（`wx069ba97219f66d99`），但那个插件**只对企业主体小程序开放**，本项目是
个人主体，后台添加后上传仍报 `80082 get plugin ... permission deny`；更糟的是
只要 `app.json` 声明了插件，未授权时**整个小程序启动失败**，不是「没声音」
而是页面打不开。所以这套方案已经换掉。

1.2.6 又踩了一个坑：音频放 `pkgTts` 分包、播放器留在主包，而微信规定
「主包不能直接引用分包资源」，真机上 `InnerAudioContext` 拿不到分包路径 ——
**读题喇叭在，但一点声音都没有**；叠加 `wx.loadSubpackage` 回调不落地时
请求会永远排队。1.2.7 起改成**预生成音频直接放主包**：

`tools/gen_tts_audio.py` 按题库规则把 174 条中文题干念成 m4a（16 kHz / 12 kbps，
0.85 MB），放进主包 `ttsAudio/`，`lib/tts.js` 按文本查 `tts-map.js` 直接播放。
**不需要插件、不需要分包、不需要联网、不需要域名白名单、不需要在后台点任何东西。**

> 体积怎么压下来的，两条：`afconvert` 会给每个 m4a 塞约 3 KB 的 `free`
> 页对齐填充块（171 个文件白占 515 KB），生成器剥掉它并修正 `moov/stco`
> 偏移表，解码出的 PCM 逐字节不变；1.2.13 起又把题干音频从 22.05 kHz /
> 16 kbps 降到 **16 kHz / 12 kbps**，174 条由 0.99 MB 降到 0.85 MB。
> 容器头是固定开销，所以实际只省约 140 KB，不是码率差的 25%。
> 改码率或朗读规则后必须跑 `python3 tools/gen_tts_audio.py --force`
> 全量重生成（默认会复用已有 m4a），否则 `--check` 会报「编码参数不一致」。

## 构建

小程序用的题库、逻辑、音频都是**生成的**，不在 git 里：

```bash
npm run mp:build     # 生成 miniprogram/generated/
```

生成内容：

| 产物 | 来源 |
|---|---|
| `generated/lib/game.js` | `src/js` 的 00-core / 10-store / 30-bank / 40-runner 拼接 + 垫片 |
| `generated/data/bank.js` | `src/data/*.json` + 配比 |
| `generated/data/audio.js` | `tools/audio_manifest.json` |
| `generated/audio/en/*.m4a` | `audio/en/` |

**逻辑只有一份**：网页版改了 `src/js` 里的纯逻辑，重新构建小程序就跟着变，
不存在两套实现各自漂移。

## 运行

> **导入前先跑一次 `npm run mp:build`。** `miniprogram/generated/` 被 `.gitignore`
> 排除，仓库里只有源码；新机器 `git clone` 后没有 `game.js` / `bank.js` / 音频映射
> 和 40 个 `.m4a`，直接导入会白屏。原始语音 `audio/en/*.m4a` 已在仓库里，
> 不需要重新生成。跑 `python3 tools/build_miniprogram.py --check` 可复核产物是否齐全。

1. 微信开发者工具 → **导入项目** → 目录选 **本文件夹**（`miniprogram/`）。
2. AppID 会自动从 `project.config.json` 读取（就是上一步写入的那个）。
3. 编译，模拟器里就能玩。

> 想用命令行（`cli open` / `preview` / `upload`）控制工具，额外还有两个前提：
> 已用微信扫码登录，且 **工具 → 设置 → 安全设置 → 开启「服务端口」**。
> 没开端口时 CLI 一律报 `IDE service port disabled`，`--port` 参数也绕不过去。
> 可执行文件：`/Applications/wechatwebdevtools.app/Contents/MacOS/cli`。

## 正式上线：备案 → 提交审核 → 发布

> **2023-09-01 起，境内主体、尚未上架的小程序必须先完成 ICP 备案才能上架。**
> 备案卡的是「提交代码审核 → 发布」，**不卡开发版和体验版**：家人扫码内测不用等。
> 但备案动辄几周且不支持加急，别等真机验收做完才想起来 —— 上传体验版的
> 同时就去提备案，两条线并行。境外主体暂不需要备案。

### 备案流程与时长

入口：<https://mp.weixin.qq.com/> → **设置 → 小程序备案 → 去备案**（后台首页
也有「去备案」提示）。不收费；个人主体主要是身份证件 + 负责人人脸核身。

| 环节 | 时效 |
|---|---|
| 微信平台初审 | 1–2 个工作日 |
| 工信部短信核验 | 初审通过后 `12381` 下发短信，**24 小时内**到 <https://beian.miit.gov.cn/> 完成核验，超时自动驳回、需重新提交 |
| 各省通信管理局审核 | 1–20 个工作日（法定上限 20 个工作日，不含周末与节假日） |
| 初审驳回后重新提交 | 再等 7 个工作日，然后重新排队 |

顺利约 1–2 周，**按 3–4 周排期**；材料被打回就是一个月以上。不支持加急，
微信平台也催不动管局。进度在后台备案页看，结果由站内信 / 模板消息 / 短信通知。
五个环节依次是：填写信息 → 平台初审 → 短信核验 → 通管局审核 → 备案成功。

### 这个项目备案要避的坑

- **教育类目别选错。** 官方前置审批清单里有「校外培训 → 教育部门允许开展
  校外培训的审批文件」。本项目是**免费识字答题游戏，无课程、无培训、无收费**，
  服务内容照实选非培训类，别写「学科培训」「幼小衔接课程」之类表述，否则会被
  要求补前置审批文件，直接卡住。`在线识字` / `幼小衔接闯关` 这类名称可能触发
  人工问询，补充说明材料里讲清性质即可。
- **提交后别改小程序信息。** 名称、主体、类目、负责人在备案期间变更，会导致备案
  信息与小程序信息不一致而被驳回；订单进入「管局审核中」后无法撤回，只能等结果。
  备案名称要与微信认证名称一致。
- **保持电话畅通。** 平台核实电话多为 `0755` 开头；主体负责人与小程序负责人
  不要用同一个手机号。人脸核身用白色/浅色纯净背景，不戴帽子、口罩、耳机。
- 备案通过后备案号会**自动**显示在小程序「更多资料」页，不用自己挂。

### 备案通过后

1. **管理 → 版本管理 → 开发版本** → 找到已完成真机验收的版本 → **提交审核**。
2. 按提示填类目、功能页面；本项目无登录、无服务端，测试账号留空并说明即可。
3. 审核通过后管理员微信会收到通知 → **版本管理 → 审核版本 → 发布**
   （普通小程序选全量发布即可）。

提交审核前把上面「上线前的真机验收」清单全部过完，别拿没验过的版本去审。

## 和网页版的差异

| | 网页版 | 小程序 |
|---|---|---|
| 奖励 | 每答对一题转一次盘 | 一局结束按正确率给 1–3 星 |
| 兑换 | 500 分兑 1 元 | 没有（星星只用来解锁徽章） |
| 存档 | localStorage | `wx.setStorageSync`，**两套独立** |
| 备份 | 下载文件 / 剪贴板 | 只走剪贴板 |
| 家长录音覆盖 | 有 | 没有 |
| 语音 | Web Audio + 文件 | `InnerAudioContext` + 包内文件 |
| 题干朗读 | 系统 `speechSynthesis`，零文件、离线可用（首次需手势解锁） | 主包 `ttsAudio/` 内预生成 m4a，离线可用、进题即播 |
| 音效 | 振荡器合成 | 同左，走 `wx.createWebAudioContext()` |
| 一局构成 | 3 语文 + 3 数学 + 4 英语混合 | 选一科 10 题；另有错题复习局 |
| 中途退出 | 不记录 | 已答题记成「未完成」局，不发星，家长页可见 |

前三个共用逻辑模块（`00-core / 10-store / 22-tts-text / 30-bank / 40-runner`）
是同一份实现，所以题库、抽题规则、错题加权、难度分档、存档迁移不会分叉。
**但一局构成不同**：网页版用 `buildRound`（3:3:4），小程序用
`buildSubjectRound`（单科）和 `buildReviewRound`（错题），两端「一局 10 题」
的科目分布不一样，成绩不能直接横向比较。这是刻意保留的产品差异，不是遗漏。

两套存档靠**备份 JSON 互通**：网页版导出的备份可以直接粘进小程序的家长页恢复
（音频录音会丢，其余都在）。

## 动态展示的边界

6 岁孩子以无意注意为主，**持续、循环、纯装饰的动画会抢注意力**。所以这里只做
「短促、跟作答结果绑定、把眼睛引向该看的地方」的一类：

- 切题时题干淡入 + 选项错峰 60ms 入场（交替 class 强制重播 CSS 动画）
- 答对时进度点弹跳、本局 ✓N 的 +1 弹入、彩纸在 620ms 窗口内演完
- 「读题」喇叭只在真的出声时脉冲 3 次，念完即停；不是常驻呼吸动画
- 答错后 1.5s 倒计时条，孩子知道还有多久才翻页，不会被毫无征兆地切走
- 结算页本局星星滚动、徽章解锁一次性光环

**不做**：背景/循环/呼吸动画、粒子叠加、全局转场叠加、连击横幅，以及任何
和题目内容无关的动效。也**不改星星账目**：过程中的 ✓N 只是视觉暂存，
真账目仍在整局结束时结算（有每日上限削减），逐题加星会和家长页审计对不上。

### 内容型演示（1.2.10 起，1.2.11 扩到三科，1.2.12 补分步）

算式、单词、拼音对孩子都是「一串看不懂的符号」：公式题不朗读（TTS 会把
`+`、`=` 念错）、拼音题朗读被归一成「看拼音，选出正确的字」、听音题只有声音
没有形。`lib/visual.js` 按科目派发四个纯函数解析器，把题目结构画出来：

| kind | 覆盖 | 答题前 | 作答后 |
|---|---|---|---|
| `math-calc` | 数学「计算」100 道 | 十进制积木画两个操作数 | `=` + 得数积木（进位 / 借位先演两帧过程） |
| `math-split` | 数学「拆数」28 道 | 原数 + 拆开的块 + `?`；凑十题另给 `A+C→十棒` 提示 | `?` 原位翻出得数积木（凑十先演两帧过程） |
| `english` | 英语 84 道 | 词族 `onset+rime`，或跟音频依次点亮的音位格子 | 正确词拆成字母卡片依次高亮 |
| `pinyin` | 语文「看拼音选字」45 道 | 声母 + 韵母 → 完整拼音 | — |

十进制积木：一根十棒 = 10（棒上有十道刻度）、一个圆点 = 1，顺带把位值
概念带出来。拆数题复用同一套积木，只是改画成「积木方程」。

四科共同纪律：

- **不改题库**：全部从题干字符串和正确选项解析。题库 JSON、生成器、
  `docs/` 产物全都不动，网页版零改动，主包只多几 KB 的 JS/WXSS。
- **不泄答案**：答题前不显示任何能直接推出答案的东西。英语听音题最典型 ——
  答案就是那个词，所以答题前只画几个空心音位格子（不显示字母），作答后才
  把正确词拆成字母；答错时重播一次单词音频，让高亮严格跟着声音走
  （1500ms 窗口够；答对 620ms 不重播，避免 1.2.8 修好的串音复发）。
  拼音合成的完整拼音题干里本来就有，不算泄答案。
- **不抢注意力**：全部一次性动画，靠 `q-enter-a/b`、`pulse-a/b` 交替 class
  强制重播；无循环、无背景、无粒子。家长面板「题目图形演示」可整块关掉，
  开关存 `settings.visualMath`（键名是 1.2.10 的历史命名，现在是三科总开关）。
- **解析不出来就静默跳过**：2 道零声母拼音（`èr` / `ěr`）、答案是大写字母的
  听音选字母题、跨词族归类、比大小、找规律、分类、应用题都退回纯文字题目。

### 分步讲解：进位 / 借位 / 凑十（1.2.12）

1.2.11 之前，进位题只给结果行一次底色提示：孩子看到 `66 + 4` 和 `70`
两个静止状态，中间「拿 4 个补上去凑成十棒」这一步完全没演。1.2.12 补上
两个中间态，全部只在**作答后**渲染，答题前连 WXML 节点都不进：

| 题型 | 帧 ① | 帧 ② | 帧 ③ |
|---|---|---|---|
| 进位 `66 + 4` | 4 个橙色圆点（要搬走） | 凑成一根绿色新十棒 | 结果行滑入 `70` |
| 借位 `94 - 7` | 9 根棒里一根标虚线（要拆） | 拆成 14 个点，划掉 7 个 | 结果行滑入 `87` |
| 凑十 `8+8=8+2+?` | 8 里拿出 2 个、剩 6 个 | 2 个凑成十棒、还剩 6 个 | `?` 原位翻出 6 |

三个时刻由 `runSteps()` 在 120 / 600 / 1080ms 依次点亮 `stepNow`，
`revealed` 到第三步才打开得数。**没有分步的题 `revealed === answered`**，
作答即揭晓，和旧版完全一样。要搬的圆点有一次向左的小位移、新十棒放大
出现，都是一次性动画；没有循环、没有背景动效。

**节奏是这轮唯一的取舍**：分步题的切题窗口从 620ms（答错 1500ms）统一
拉到 **1900ms**，答错时的倒计时条同步改成 1.9s。只影响 49 道题（进位 21 +
借位 21 + 凑十 7），其余 551 道节奏不变。家长面板有独立的
「分步讲进位 / 借位」开关（`settings.visualSteps`，默认开），关掉后积木图
照旧、节奏立刻恢复 620 / 1500；「把题目画出来」总开关关掉时它会禁用。
两个键都不写进共用 Store 的默认字段，靠 `migrate()` 只补不删随存档保存。

所有分步定时器都走 `later()`，切题、退出、结算的 `clearTimers()` 会一并
清掉，不会把上一题的揭晓动作漏到下一题。帧数据由 `visual-math.js` 的
`calcSteps()` / `makeTenSteps()` 纯函数生成，题库和网页版产物仍然零改动。

## 1.2.13：按「小程序为主」修的五件事

用户确认孩子平时主要用小程序，所以**网页版不补复习局、不补可视化**，
两端的功能差距是刻意保留的（见主 README「微信小程序」一节）。

**星星按正确率折算（真 bug）。** `lib/stars.js` 的 `forCorrect()` 原来用绝对
题数阈值（9 题 3 星 / 6 题 2 星），而复习局「不足一局就出几道算几道」，
首页错题 ≥3 道就放入口 —— 3 道错题全做对只能拿 1 星。现在改成
`forCorrect(correct, subject, total)` 按 `correct/total` 判 0.9 / 0.6，
普通局 10 题逐档与旧版完全一致；`total < 3` 固定 1 星防刷（2 题全对拿
3 星太便宜）。每日 60 星上限 + 错题 `cleared` 机制兜住长局。

**复习局独立语义（同源的第二个 bug）。** `finishSession` / `abandonSession`
现在往 session 写 `review` 标记，`levelDetailOf()` 评估难度档时跳过复习局 ——
复习局专挑不会的题，正确率天然偏低，以前算进来会把孩子一直压在基础档。
老存档没有这个字段，按普通局处理。`30-bank.js` / `40-runner.js` 是共用逻辑，
`docs/app.js` 会跟着同步，但网页版没有复习局，行为零变化。

**答案不进答题前的数据层。** 以前 `visual.forQuestion()` 返回的对象里已经
带着 `result`（得数积木）、`parts[].solved`（拆数答案）、`after.word`（英语
正确词），只靠 WXML 的 `revealed` 挡着 —— 模板改错一行就泄题。现在
`lib/visual.js` 把这三个字段从 `forQuestion()` 剥掉，新增 `reveal()` 只在
作答后返回、`merge()` 在 `onOption` 同一次 `setData` 里合并回去。答题前的
`page.data.visual` 里根本不存在答案字段。`steps`（进位/借位过程帧）是讲解
数据、只在 `answered` 之后渲染，留在前半边 —— 切题窗口必须进题时就知道
这题有没有分步。无头测试对全 600 道题断言「零答案字段」。

**音位格子按音素数。`visual-english.js` 以前用 `w.length`，`six` 会画 3 格，
实际是 /s/ /ɪ/ /k/ /s/ 四个音。现在 `phonemeCount()` 把 `x` 算两个音、
`sh/ch/th/wh/ck/ph/ng` 和叠字母算一个；长词仍 clamp 到 3~5 格，只给节奏
示意（`nose`/`snake` 的 magic e、`juice` 的双元音不逐一数，不值当）。

**首页按钮报本局题数。** 以前「复习错题（37）」点进去只做 10 道，改成
「复习错题（本局 10 题）」；总错题数在家长页「待巩固的题」看。

另外两项在主 README 的音频章节：题干音频降到 16 kHz / 12 kbps（0.99 →
0.85 MB），以及 `check_audio.py` 的解码缓存（全量 30 秒 → 命中 1.3 秒）。

## 1.2.14：结算页复习入口 + 两处健壮性

**复习局不再隐式用语文阈值。** `finish()` 原来是

`review` 档（同样 9/6），`finish()` 显式传 `'review'`。当前三科阈值相同，

无头断言 387 → 409 项，新增覆盖：结算页四种局面（有错题 / 全对 /
复习局 / 错题超一局上限）、复习按钮跳转、缺音频时不画喇叭、review 档隔离。

## 1.2.17：修掉七个真机可复现的 bug

   过滤，结果恒为 0，三科永远停在「第 1 关」。**不去改共用 Runner**（那样会
   同步到 `docs/app.js`），改成 `subjectOf(s)` 从 `s.items[].subject` 推断：

   任何一科。老存档里已经打过的局也能立刻点亮，不用迁移、不用等新局。

第三批第 1 项，不加功能。全部落在小程序端，`src/js/`、`docs/`、题库、
生成器、音频一行未改，网页版产物哈希不变。

**根因**：`stars.forCorrect()` 里写的是 `var n = total || 10`。`0` 在
JS 里是假值，于是显式传 `total = 0` 被当成「调用方没传」，按 10 题标准局
算 —— `forCorrect(9, 'math', 0)` 会给 3 星。真实结算链路里
`play.onLoad()` 已经挡了 `round.questions.length === 0`，所以真机暂时踩不到；
但 `result` 页读 `lastResult` 时 `correct / total` 会除零出 NaN，今日局数
也会把空局算成一局，属于「一旦有人改了抽题逻辑就会连锁出错」的隐式依赖。

四处一起收：

1. **`lib/stars.js`** — 只有 `undefined` / `null` 才按 10 题标准局；显式
   `0` / 负数 / NaN 返回 **0 星**。空局是「一题都没答」，不是「答错」，
   所以不吃「全错也保底 1 星」那一档；这条产品语义写进了函数注释。
   另外把 `correct > total` 的脏数据夹回题数，避免除出 >100% 白拿高星。
   正常局逐档不变：9→3、6→2、全错→1、3 题复习局全对→3。
2. **`pages/play/play.js` 的 `finish()`** — 第二道闸：`total === 0` 时
   `clearTimers()` + toast「这一局没有题目」+ `navigateBack`，**不调
   `awardPoints`、不写 sessions、不设 lastResult、不跳结算页**。放在算星
   之前，也不设「未完成局」—— 一道题都没答，没什么可记的。
3. **`pages/result/result.js`** — `pct` 改成 `r.total > 0 ? ... : 0`，
   异常 / 旧存档里的 0 题成绩不会把 NaN 带进 setData（文案、彩纸、emoji
   都会落到错误分支）。
4. **`lib/rewards.js` 的 `roundsToday()`** — 明确标成 0 题的空局不算
   「今天玩了一局」，与折线一致。这里用 `s.total === undefined || s.total > 0`
   而不是简单的 `> 0`：老存档 / 精简备份的 session 可能没有 total 字段，
   仍按完成局算；折线因为要拿 total 当分母，必须要求 `total > 0`，两者
   只在「显式 0 题」这一点上同口径。家长页「今日局数」直接复用此函数。

**取舍**：没改 `src/js/40-runner.js` 的 `finishSession`（那会同步到
`docs/app.js`），也没改 `buildReviewRound` 的失效 qid 过滤 —— 那是另一条
待办，不属于这次的 0 题边界。

无头断言 621 → 658 项。新增覆盖：四科 + review 的 0 题 / 负数 / NaN /
字符串 0、省略与 null 的旧调用兼容、correct 越界夹取、0 题结算入口的
不发星 / 不写 session / 不写 lastResult / 不跳转 / 有提示 / 掐定时器、
同一实例换正常局仍能结算并拿 3 星、0 题结算页零 NaN、今日局数排除空局
且兼容缺 total 的老 session。

## 已知风险

- `wx.createWebAudioContext()` 需要基础库 **2.19.0+**。拿不到上下文时音效退化
  成震动，游戏本身不受影响。**真机上务必验一遍对错音效**。
- `wx.setInnerAudioOption({ obeyMuteSwitch: false })` 只作用于 **InnerAudioContext**
  （也就是题干语音）。`app.js` 在 `onLaunch` 里、创建任何音频实例之前调用，所以
  iOS 静音开关打开时听音题照常出声。注意实例上的 `obeyMuteSwitch` 属性从基础库
  2.3.0 起已不生效，只能用这个全局接口。
  **它管不到 WebAudioContext**：答对/答错的合成音效在 iOS 静音模式下很可能不响，
  这是平台限制，微信没有给 WebAudioContext 提供对应开关。要让音效在静音下也响，
  只能把 `sfx.js` 改成播放预生成音频文件、同样走 InnerAudioContext。改造前不要把
  「静音下音效要响」当必过项。真机无声时看 vConsole 里 `[audio]` / `[app]` 的日志。
- 题干语音是包内绝对路径（`/generated/audio/en/*.m4a`），不联网、不需要域名白名单。
  第 2 题之后是程序触发的自动播放，某些机型可能不响 —— 喇叭按钮可以手动重播。
- **题干朗读也走 InnerAudioContext**，所以同样受 `obeyMuteSwitch:false` 保护。
  音频是主包内绝对路径（`/ttsAudio/*.m4a`），和英文单词音频同一条链路，
  不联网、不预下载、不需要域名白名单。真机读题没声时先看 vConsole 的
  `[tts] 播放开始 / 播放失败` 日志：前者没打印说明没走到播放层（检查家长
  开关、`tts-map.js` 是否命中），后者带 errMsg 则说明路径或格式有问题。
