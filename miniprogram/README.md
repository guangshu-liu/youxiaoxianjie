# 微信小程序版

同一套题库、同一套组局逻辑，界面用 WXML 重写，奖励从「转盘抽奖 + 积分兑现金」
改成**确定性的星星与徽章**。

## 为什么改掉了转盘

微信《常见拒绝情形》3.2.8.9 把「有奖竞猜和抽奖」列为违规，积分兑换现金也属于
高危项。即使只做体验版不过审，这套机制也不值得留着 —— 而这个游戏真正的动力
本来就不是赌运气。

现在的规则：一局 10 题，答对 **8–10 题 3 星**、**5–7 题 2 星**、**0–4 题 1 星**。
星星累计到 **10 / 30 / 60 / 100** 各解锁一个徽章（小苗 / 小星 / 火箭 / 大王）。

## 前置

### 1. 安装开发者工具

[下载地址](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
Mac 上也可以 `brew install --cask wechatwebdevtools`。

### 2. 注册小程序，拿 AppID

只有注册后才能**真机预览**和**上传体验版**；游客模式只能在电脑模拟器里跑。
注册免费，个人主体即可，需要身份证 + 银行卡实名。

1. 打开 <https://mp.weixin.qq.com/> → **立即注册** → 选 **小程序**（不要选订阅号/服务号）。
2. 用一个**没在微信公众平台注册过**的邮箱，填密码，去邮箱点激活链接。
3. 主体类型选 **个人**，填身份证姓名/号码、管理员手机号，短信验证。
4. 登录后台 → **开发管理 → 开发设置**，复制 **AppID**（`wx` 开头 16 位）。

> 体验版**不需要**：微信认证（约 30 元）、ICP 备案、类目审核、代码审核。
> 这些都是「正式发布」才需要的，本轮用不到。

### 3. 把 AppID 写进项目

```bash
npm run mp:appid -- wx1234567890abcdef   # 会先校验格式再写盘
npm run mp:appid -- --check              # 随时复核当前用的是不是正式号
```

> **只需要 AppID，不需要 AppSecret。** 密钥是服务端凭据，只在调用
> `code2Session` / 获取 access_token 这类接口时用；本项目没有服务端，
> 上传代码靠的是开发者工具里登录的微信账号。
> **绝对不要把 AppSecret 写进仓库或前端代码** —— 拿到它就能以你的
> 小程序身份调用服务端接口。

## 构建

小程序用的题库、逻辑、音频都是**生成的**，不在 git 里：

```bash
npm run mp:build     # 生成 miniprogram/generated/
```

生成内容：

| 产物 | 来源 |
|---|---|
| `generated/lib/game.js` | `src/js` 的 00-core / 10-store / 30-bank / 40-runner 拼接 + 垫片 |
| `generated/data/bank.js` | `src/data/*.json` + 配比 |
| `generated/data/audio.js` | `tools/audio_manifest.json` |
| `generated/audio/en/*.m4a` | `audio/en/` |

**逻辑只有一份**：网页版改了 `src/js` 里的纯逻辑，重新构建小程序就跟着变，
不存在两套实现各自漂移。

## 运行

1. 微信开发者工具 → **导入项目** → 目录选 **本文件夹**（`miniprogram/`）。
2. AppID 会自动从 `project.config.json` 读取（就是上一步写入的那个）。
3. 编译，模拟器里就能玩。

## 发体验版给家人

1. 开发者工具右上角点 **上传**，填版本号（如 `1.0.0`）和备注。
   - 「上传」按钮不出现，通常是 AppID 还是 `touristappid`，跑 `npm run mp:appid -- --check` 确认。
2. 打开 <https://mp.weixin.qq.com/> → **管理 → 版本管理**。
3. 找到刚上传的开发版本 → **选为体验版**。
4. **管理 → 成员管理 → 体验成员**，把家人的微信号加进去（上限 90 人）。
5. 在版本管理页下载 **体验版二维码**，发给家人扫码。

**体验版不需要提交审核**，所以不会触发类目和抽奖相关的审核问题。
体验成员之外的人扫这个码打不开——这是预期行为。

## 上线前的真机验收

无头测试覆盖不了音频和手势，下面几条必须在真手机上过一遍：

- [ ] 首页星星数、徽章、进度条显示正常
- [ ] **听音选字母题进题就自动播一遍**（第 1 题和第 5 题都试）
- [ ] 点喇叭能重播
- [ ] 答对 / 答错分别有对应音效（iPhone 静音开关拨到静音也要响）
- [ ] 答错时正确答案标绿、解释条出现
- [ ] 连点选项不会重复计分（第二次点击无效）
- [ ] 一局 10 题走完 → 结算页星星正确 → 「再来一局」能开新局
- [ ] 杀掉小程序重进，星星还在
- [ ] 家长页：7×8 能进；答错 3 次锁 30 秒；杀掉重进仍然锁着
- [ ] 家长页「复制备份」能粘贴出 JSON；粘贴回「恢复」后数据一致

## 和网页版的差异

| | 网页版 | 小程序 |
|---|---|---|
| 奖励 | 每答对一题转一次盘 | 一局结束按正确率给 1–3 星 |
| 兑换 | 500 分兑 1 元 | 没有（星星只用来解锁徽章） |
| 存档 | localStorage | `wx.setStorageSync`，**两套独立** |
| 备份 | 下载文件 / 剪贴板 | 只走剪贴板 |
| 家长录音覆盖 | 有 | 没有 |
| 语音 | Web Audio + 文件 | `InnerAudioContext` + 包内文件 |
| 音效 | 振荡器合成 | 同左，走 `wx.createWebAudioContext()` |

两套存档靠**备份 JSON 互通**：网页版导出的备份可以直接粘进小程序的家长页恢复
（音频录音会丢，其余都在）。

## 已知风险

- `wx.createWebAudioContext()` 需要基础库 **2.19.0+**。拿不到上下文时音效退化
  成震动，游戏本身不受影响。**真机上务必验一遍对错音效**。
- iOS 静音开关会静音所有音频；`app.js` 里已经调了
  `wx.setInnerAudioOption({ obeyMuteSwitch: false })` 关掉这个行为。
- 题干语音在第 2 题之后是程序触发的自动播放。若某些机型上不响，喇叭按钮
  仍然可以手动点。
